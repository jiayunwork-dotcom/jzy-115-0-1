我这学期带一门暖通设备选型的课，想让学生自己搭一个能常驻运行的风机选型核算后端，专门解一件事：给定一段风管和一台风机，求它们真正稳定运行的那个工作点，再顺带按相似律换算不同转速下的表现。风管这边，学生要输入管长、内径、沿程摩阻系数以及若干局部阻力系数之和，空气物性按二十摄氏度固定；管阻压升等于摩阻项与局部损失项之和乘以动压，动压里的流速由体积流量除以圆管截面积换算而来，所以同一个流量、同一个截面，流速只能有一个口径，不许管阻算一套流速、别处又换一套。风机这边，输入是一条特性曲线，可以是若干组流量对全压的采样点，也可以是拟合好的二次曲线；当流量落在采样范围之外时，服务要么明确拒绝、要么按事先声明的一种方式外推，不能默默给个数糊弄过去。

真正的核心是求交点：让风机能提供的全压恰好等于风管在该流量下需要的压升，这条方程一般不是线性的，要用括号法或牛顿法之类的求根手段解出交点流量，再回代得到工作点全压和管内流速。这里有几条关系必须同时立得住，我会让学生逐条写成自动化测试盯着：把风管加长，交点流量应当下降，且下降的方向要和两条曲线各自的形状一致；管阻近似正比于流量的平方，所以流量翻一倍、管阻压升大约变成四倍；流量为零时管阻压升归零，风机在这一点给出的是它的静压；空气密度调高，同一个流量下管阻变大，交点流量随之减小。相似律那部分单独成立：转速从某一值提到另一值时，流量与转速成正比、全压与转速的平方成正比、轴功率与转速的立方成正比，但要注意，转速一变风机曲线整体就变了，新的交点必须重新求解，绝不能拿旧交点流量直接乘个转速比就交差。

服务对外只经 HTTP 提供接口，一个用来给定风管与风机曲线求当前工作点，一个用来在此基础上指定新转速、返回相似律换算后的重新求交结果。管径为零、管长为负、密度非正、风机曲线为空这类非法输入，要在开始求解之前就被挡下并返回带说明的错误响应，不能让它们流进求根过程里。请预置一个可以手算核对的算例：一段直管配一台内联风机，交点流量应当落在给定的两个采样点之间，把这个算例固化下来当回归基准。

实现选用 Python 3.12 搭配 FastAPI，按职责把管阻计算、风机曲线求值、求根、相似律换算、输入校验和 HTTP 层拆成彼此独立的模块，不要把核心逻辑堆进单个大文件。附上自动化测试覆盖上面这些关系，尤其盯住压升随流量平方变化和转速相似律这两组。用一份 Dockerfile 基于 python:3.12-slim 把服务打包成单个容器，构建后能直接起来对外服务。范围就限定在单管加单台风机的工作点求解，不涉及多环管网平差，也不做任何前端页面或下单流程。
